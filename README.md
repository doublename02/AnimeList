# Anime Shelf · 我的动画手账

记录收藏动画的个人静态网站，作品资料来自 Bangumi，适配电脑与手机。无需构建、无需安装依赖，已部署到 GitHub Pages。

**在线访问：[Anime Shelf](https://doublename02.github.io/AnimeList/)**

## 功能

- 按中文名或原名搜索 Bangumi 动画作品并添加到书架。
- 默认沿 Bangumi 前传、续集关系补齐该系列的 TV / 网络动画季度，可取消勾选，仅添加单个作品。点击已收藏作品的“补齐季度”也能更新系列。确认保存前会展示本次整理的全部条目，失败或取消不会写入部分数据。
- 展示封面、中日文名称、制作公司、首播年份和季度。
- 编辑作品资料和个人短评，移除作品。
- 按名称或制作公司搜索收藏，按年份、季度筛选，按添加时间、放送时间或名称排序，均可切换正序、倒序。时间正序为从早到晚，倒序为从晚到早；名称按中文排序规则切换方向。
- “添加时间”按系列成组显示，正序时组内按季度、篇章从早到晚排列，倒序时也反转组内顺序；后续补入新季仍保持整组连续。
- GitHub 管理员登录，修改后自动提交清单，支持网络失败草稿恢复和跨设备冲突处理。
- 访客只读，支持导出 JSON；管理员可导入、编辑、删除及恢复旧本地备份。

网站不记录观看状态。

## 本地预览

在项目目录运行 `python -m http.server 4173`，然后访问 http://localhost:4173 。请通过 HTTP 打开，直接双击 HTML 无法加载 JSON。

## 使用

- 点击“添加作品”，输入中文名或原名搜索 Bangumi，点击收藏后确认资料。
- 记录封面、中日文名称、动画制作公司、首播年份和季度及短评。
- 季度按首播月份推算：1–3 月为冬季、4–6 月为春季、7–9 月为夏季、10–12 月为秋季。跨季度播出的作品仍归入首播季度。
- 制作公司优先取 Bangumi 的“动画制作”字段，资料缺失时可手动补充。
- 完成一次性云端配置后，管理员修改先保存本地草稿，再自动提交 GitHub；未登录访客只读。
- “导出清单”下载完整的 `library.json` 作为备份。管理员导入后自动同步；也可以手动替换仓库里的 `data/library.json` 并提交。
- 导入会替换当前清单，建议先导出备份。

清单从个人作品文档导入：原文 568 项，其中“致我深爱的每个你／致深爱你的那个我”拆分为两部独立电影，得到 569 个原始条目。随后根据 Bangumi 前传、续集关系，补入 347 个电视或网络动画季度、连续篇章，当前共 916 个条目，195 个系列包含多个季度或连续篇章。完整系列列表见 [多季度系列清单](docs/series.md)。

同系列统一名称前缀，保留篇章副标题及分段；例如《刀剑神域》整理为第一季、第二季、第三季·爱丽丝篇及第三季的异界战争分段。展示序号按本清单连续季度与篇章整理，原始 Bangumi 中文名称保存在 `sourceTitle`，日文名称保存在 `original`。不会自动添加电影、OVA、总集篇或独立特别篇；原来收藏的电影保留。分段正篇（如《进击的巨人》最终季完结篇）保留在对应季中。

同名新旧版本按个人选择收录《钢之炼金术师 FULLMETAL ALCHEMIST》（2009）、《猎人》（2011）、《狼与香辛料 行商邂逅贤狼》（2024）和《福星小子》（2022）。《Love Live! 学园偶像祭》按动画《Love Live!》收录；《恶魔的破坏》采用网络动画版。

部分尚未播出的作品资料可能继续变动，以 Bangumi 最新资料为准。后续通过网页维护清单，网站使用的本地封面保留在 `AnimeList/Covers/`。

## 更新清单并同步网站

自动同步代码采用 GitHub App + Cloudflare Workers，不需要云端数据库。部署配置见 [自动同步说明](docs/auto-sync.md)。

1. 完成一次性 App 安装与 Worker 密钥配置，并在 `sync-config.json` 填写接口地址。
2. 点击网站“管理员登录”，使用 `doublename02` 授权。
3. 添加、修改、删除或导入后自动提交；状态栏显示保存结果，Pages 随提交自动部署。

管理员跨设备登录直接读取 GitHub 最新清单。访客每次加载读取已发布的公开清单，浏览器旧本地数据不会自动覆盖云端。未同步草稿仍保存在原浏览器，冲突需要确认合并后再写入。

## 导入格式

接受 `.json` 文件，内容为作品数组。推荐直接使用网页导出的文件。`id` 是唯一的正整数 Bangumi 作品 ID，`title` 是非空作品名称，两项必填，其余字段可省略。

```json
[
  {
    "id": 23686,
    "title": "刀剑神域",
    "original": "ソードアート・オンライン",
    "cover": "https://lain.bgm.tv/pic/cover/l/2e/c8/23686_e36x9.jpg",
    "studio": "A-1 Pictures",
    "year": 2012,
    "season": "summer",
    "date": "2012-07-07",
    "note": "",
    "addedAt": "2026-10-18T02:38:00.000Z"
  }
]
```

`season` 可填 `winter`、`spring`、`summer`、`autumn`，或留空。封面支持 HTTPS 链接，或项目内 `AnimeList/Covers/` 下的相对路径；使用本地封面时，图片也需提交到仓库。导入文件最大 10 MB，最多 10000 部作品，ID 不能重复。旧清单中的观看状态字段会在读取时移除。

成组作品额外保存 `seriesId`（系列标识）、`seriesTitle`（系列名称）、`seriesOrder`（组内顺序）和 `sourceTitle`（Bangumi 原始名称）。同系列统一 `addedAt`；这些字段在导入、编辑、导出时保留，保证“添加时间”下仍连续显示。未公布的放送日期、年份、季度、制作公司可留空。

## 部署说明

本仓库已启用 GitHub Pages，使用 `.github/workflows/pages.yml` 发布。提交到 `main` 分支会自动部署，也可以在 Actions 页面手动运行 **Deploy GitHub Pages**。

如需部署到其他仓库：

1. 在 GitHub 创建仓库，把本目录文件上传到仓库的 `main` 分支，包含隐藏目录 `.github`。
2. 打开仓库 **Settings → Pages → Build and deployment**，Source 选择 **GitHub Actions**。
3. 打开 **Actions → Deploy GitHub Pages → Run workflow**（后续提交到 main 会自动部署）。
4. 等待成功后，打开部署结果中的网址，一般是 `https://你的用户名.github.io/仓库名/`。

部署仅打包网页、JSON 和封面。若仓库本身公开，仓库内所有已提交文件仍可被访问。无需 Token，不要把 GitHub 或 Bangumi 密钥写进网页。

## 数据来源及限制

使用 Bangumi 公共 API：`POST /v0/search/subjects`（动画类型 2）和 `GET /v0/subjects/{id}`。搜索及读取新作品需要访问 api.bgm.tv，远程封面需要访问 lain.bgm.tv；跨域策略、网络及 API 限流可能影响使用。API 故障会显示提示，已经保存的文字资料仍可浏览。默认不搜索 NSFW 条目。

访客只读。管理员经 GitHub App 授权后才能修改和提交清单，服务端同时校验账号数字 ID、登录名、网页来源及文件版本。保存接口固定写入 AnimeList 的 data/library.json；密钥仅保存在 Cloudflare，不写入公开网页。

Bangumi 官方 API 文档：[bangumi.github.io/api](https://bangumi.github.io/api/)
